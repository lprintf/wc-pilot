# 客服后台 Demo TODO（2026-09-06）

## 1. 目标

开发一个供客服人员使用的 Web 后台 Demo，客服可以：

- 在用户列表中人工选择目标用户；
- 查看该用户的历史对话记录；
- 输入并发送人工客服消息；
- 明确区分用户消息、AI 消息和人工客服消息；
- 在 Demo 阶段优先打通真实后端数据链路，界面保持简单、可演示。

本任务只覆盖客服内部后台，不包含企业微信管理后台、客服人员复杂权限体系和完整生产级实时通信能力。

## 2. MVP 范围

### 2.1 页面布局

- [ ] 新增客服后台页面，建议采用三栏布局：用户列表、对话区、用户信息区。
- [ ] 用户列表展示昵称、头像、最近消息摘要、最近活跃时间和未读数量。
- [ ] 支持按昵称或内部用户 ID 搜索用户。
- [ ] 支持点击用户切换当前会话，并在切换后加载历史消息。
- [ ] 对话区按时间顺序展示消息，区分发送方和消息来源。
- [ ] 对话区支持历史消息分页或滚动加载，避免一次加载全部记录。
- [ ] 用户信息区展示安全范围内的用户资料，不直接暴露 `external_userid`。
- [ ] 输入框支持发送文本消息，支持 Enter 发送、Shift+Enter 换行。
- [ ] 发送中禁用重复提交，并展示成功、失败和重试状态。

### 2.2 后端接口

- [ ] `GET /api/admin/users`：返回可供客服选择的用户列表，支持搜索、分页和排序。
- [ ] `GET /api/admin/users/{user_id}/conversation`：返回指定用户的历史消息。
- [ ] `POST /api/admin/users/{user_id}/messages`：创建并发送人工客服文本消息。
- [ ] `GET /api/admin/users/{user_id}`：返回用户基本资料和会话摘要。
- [ ] 所有后台接口统一返回结构化错误，至少覆盖用户不存在、消息为空、发送失败和未授权。
- [ ] 后端通过内部 `user_id` 关联数据，禁止前端直接拼接或依赖微信外部身份标识。

### 2.3 数据模型

优先复用现有 `app_user`、`user_identity`、`customer_profile` 和会话消息表；如当前消息表无法表达来源，再补充字段或迁移：

```text
conversation_message
  id
  conversation_id
  user_id
  sender_type       # user / ai / human_agent / system
  message_type      # text（MVP）
  content
  source            # wechat_kf / llm / admin
  source_message_id nullable
  send_status       # pending / sent / failed
  occurred_at
  created_at
```

- [ ] 为人工客服消息保留发送状态和错误信息，避免网络失败时前端误显示为已发送。
- [ ] 为消息增加稳定排序字段，处理同一时间戳下的消息顺序。
- [ ] 对用户列表查询增加最近消息和未读数量所需的索引。
- [ ] 确认人工发送消息与企业微信 `kf/send_msg` 的调用及落库顺序，保证重试不会重复发送。

## 3. 鉴权与安全

- [ ] 增加最小可用的后台鉴权：Demo 可先使用配置的单一客服账号或开发环境登录态。
- [ ] 后端接口必须在服务端校验客服身份，不能仅依赖前端隐藏页面。
- [ ] 限制客服可访问的数据范围，避免通过修改 URL 查看非授权用户。
- [ ] 日志中不得输出消息全文、密钥、access token、Session 或完整外部用户标识。
- [ ] 消息内容进行长度限制和基础输入校验；前端展示时避免不安全 HTML 注入。
- [ ] 发送人工消息时记录操作人和操作时间，便于后续审计扩展。

## 4. 实现顺序

- [ ] 1. 盘点现有路由、消息表和企业微信客服发送封装，确定复用边界。
- [ ] 2. 先实现用户列表和历史消息只读接口。
- [ ] 3. 创建客服后台页面和静态 Mock 数据，完成三栏交互。
- [ ] 4. 将页面接入真实接口，补齐加载、空状态、错误和分页状态。
- [ ] 5. 接入人工客服消息发送，处理幂等、失败重试和消息回显。
- [ ] 6. 增加鉴权、审计字段、敏感信息脱敏和基础安全校验。
- [ ] 7. 使用本地或测试环境完成端到端验收。

## 5. MVP 验收标准

- [ ] 客服打开后台后能够看到用户列表，并能搜索和人工选择用户。
- [ ] 选择用户后能够看到该用户的历史对话，消息发送方和时间展示正确。
- [ ] 客服发送文本后，页面立即显示明确的发送中状态，并在成功后显示已发送。
- [ ] 企业微信发送失败时，页面显示失败原因或可重试入口，数据库不会产生错误的已发送记录。
- [ ] 刷新页面或重新选择用户后，已发送人工消息仍能从后端正确加载。
- [ ] 空用户列表、空历史记录、用户不存在、接口超时和发送失败均有可理解的提示。
- [ ] 普通用户无法通过接口或修改参数访问客服后台数据。
- [ ] 不影响现有 AI 自动回复和微信客服消息同步流程。

## 6. 暂不纳入 MVP

- [ ] 多客服并发抢单、转接、排队和会话分配。
- [ ] 客服账号、角色、组织架构和细粒度 RBAC。
- [ ] 图片、文件、语音、视频、富文本和快捷回复。
- [ ] WebSocket 实时推送；第一版可采用手动刷新或短轮询。
- [ ] 完整统计报表、满意度评价和会话标签体系。
- [ ] 企业微信官方“会话内容存档”数据源接入；仍沿用当前客服消息数据边界。
